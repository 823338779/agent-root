## 冲突与缺口登记

下表登记跨文档、跨仓库的系统性冲突与缺口。各主题的完整契约、证据和验收方式位于对应主体文档中。

| 主题 | 跨仓证据与当前判断 | 复刻要求 | 关联文档 |
|------|---------------------------|------------|------------|
| 实时执行与持久化状态不是同一事实源 | 产品实现同时存在进程内执行状态、实时事件和持久化记录；测试资产覆盖重连、取消和恢复，但本轮未运行。进程存活不能替代可恢复的持久状态。 | 为 execution、connection 和 persisted conversation 分别建模；事件必须带稳定执行标识和序号；重连先补历史再接实时流。 | T05、T18、T21、T22、P03 |
| 业务资源存在不代表依赖工具已授权 | Nova 的资源挂载、工具注册、Skill/MCP 可见性是独立链路；测试期望也不能越过能力边界。 | resolver 不得因知识库、项目或场景存在而旁路注入工具；统一经过注册、scope、mandatory 和 MCP 可见性判定。 | P14、P17、P18、P20、T08、T09、T10 |
| 外部系统只能部分逆向 | CAN Gateway、模型 Provider、MCP Server、企业通信、认证与数据源的仓内信息主要是调用方契约；对端内部实现不可由此证明。 | 将“仓内观察契约”和“推荐对端设计”分层；先实现可替换 Stub，再按超时、幂等、认证、审计和兼容策略建设生产对端。 | T23、T24、T25、T26、T27 |
| 测试资产不等于本轮运行证明 | 两个测试仓提供 DSL、Runner、E2E flow 和预期结果，但本轮未执行构建或测试。 | 只把静态测试定义记为测试资产证据；迁移后必须按 Q01-Q11 的环境矩阵实际执行并保存证据包。 | Q01-Q11、01-evidence-policy |
| 测试仓存在凭据暴露风险 | 静态审计发现 UI E2E 资产存在源码默认口令回退，以及被跟踪的发布环境配置中包含非空共享密钥。文档未复制秘密值。 | 作为 P0 处理：立即吊销/轮换、清理历史、删除源码回退与被跟踪秘密，改由 CI secret 注入，并对日志/截图/trace 做脱敏。 | Q08、Q10、Q11、T20 |
| CI Java 门禁口径存在结构性冲突 | 聚合工程包含 Java 17 模块和 Java 21 产品应用；现有工作流的 JDK/测试阶段组合不能完整证明全 reactor 编译与测试均通过。 | 发布门禁显式采用能编译 Java 21 的 JDK，分别执行全 reactor compile/test 与前端 build；不得把跳过测试的打包任务视为测试通过。 | Q01、Q11、T01 |
